Switchboard Model Registry

One committed table now says which model and effort each role runs on Claude and on Codex. Switchboard turns that table into each host's own role files, and checks afterwards what a dispatch actually ran.

What you can do now

inspect --roles

Read the table

See every role with its requested Claude and Codex model, effort and cited claim, plus the latest observed value per host.

apply · apply --write

Generate role files

Preview, then write role-<role> files for both hosts. Switchboard only overwrites or prunes files its ledger proves it wrote.

observe --host claude|codex --latest

Record what ran

Read model, effort and agent type from the newest host transcript (never message text) and append a receipt.

Proven on the real hosts on 2026-11-09 (R5). A dispatch by role name ran exactly the pinned model and effort on all four paths: the Agent tool and a Workflow agent in VS Code, claude -p, and a Codex spawn. On the headless paths the parent session ran a different model, so the match comes from the role file, not from inheritance.

How a role travels

The registry is the requested value, the ledger is what was resolved into files, and receipts are what the host observed. inspect --roles puts requested and observed side by side.
